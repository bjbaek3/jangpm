## 1. 배경과 근거 (실측)

클린룸(`cases/2026_김민재_해고무효_클린룸`, 동일 입력 md5 확인) vs
골든(`cases/2026_김민재 해고 무효`) 대조 결과, 파이프라인은 **기계층**(MST·
연혁 라벨·판례ID·핀 형식·PASS 도달)에서 재현적이나 **판단층**에서 변동한다:

| 결함 | 실측 내용 |
|---|---|
| C1 | 클린룸이 지연이자 연 20%(근로기준법 제37조·시행령 제17조)를 리서치째 누락 → 청구취지에 전파(의뢰인 불이익) |
| C2 | 해고예고수당 병합 법리(2017다16778 계열)를 클린룸 리서치가 미발견 — 골든은 확보 |
| C3 | 퇴직금 청구(근로관계 종료 전제) vs 해고무효확인(존속 전제) 정합성 검토를 클린룸이 미기재 |
| C4 | 동일한 제56조 `[행위시 확인]` 부기 누락을 골든 검증자는 ✅, 클린룸 검증자는 ⚠️ — 판정 갈림 |
| C5 | 동류의 근거 없는 부존재 단정을 ⚠️(골든 소장) vs ❌(클린룸 준비서면)로 상반 판정 — 경계가 "확인필요 태그 병기 여부"에 의존 |
| C6 | 부존재 과단정이 양쪽에서 위치를 바꿔 비결정적으로 발생 — 준비서면 1차 FAIL이 양쪽 공통 |

목적: 판단층(리서치 스코프·검증 재량·draft 사실 규율)을 규칙으로 인코딩해
단일 실행의 리콜·재량 편차를 줄인다. 독립 검증 게이트 구조는 불변.

## 2. 설계 결정 4건

### 결정 ① 필수 리서치 체크리스트 — `rules/요건사실.md` 확장

- 각 청구유형 항목에 **"필수 리서치"** 절을 추가한다(단일 사전 유지, 새 파일 없음).
- 공통 규칙: **금전청구가 포함된 사건은 지연이자 법령 세트가 필수** —
  민법 제379조·제397조, 소송촉진 등에 관한 특례법 제3조 + 법정이율 대통령령,
  임금채권이면 근로기준법 제37조 + 시행령 제17조.
- 병합 규칙(해고 사건): 해고무효확인 + 금전청구 병합 시
  (a) 해고예고수당의 병합 정합성 법리(해고 유효 여부와 무관 — 2017다16778 계열)
  (b) 퇴직금 청구와 근로관계 존속 전제의 정합성 검토 항목. — C3도 이 항목이 커버.
- `legal-research/SKILL.md` 절차에 **스코프 고정 단계** 추가:
  쟁점 리서치와 별도로, `사건컨텍스트.청구[]`의 유형별 필수 리서치 항목을
  요건사실.md에서 로드해 스코프에 포함한다. 산출물 말미에
  **"필수 리서치 커버리지"** 절(항목 / 커버 여부 / 미커버 사유)을 기재한다
  (변호사 검수용 — verify 판정 대상 아님).
- 사전에 없는 청구유형: 기존 관례 유지(보고 후 통상 진행, 추후 사전에 추가).

### 결정 ② `[행위시 확인]` 부기 = 핀의 일부 (C4·이관 손실·P2-7 통합 해소)

- `rules/인용규칙.md` §7: **부기는 핀 블록의 일부**이며 리서치→서면 복사 시
  함께 이관함을 명문화.
- `draft-complaint`/`draft-brief`: "리서치의 핀 블록(출처 핀 + `[행위시 확인…]`
  부기)을 통째로 복사한다" 명시.
- `verify-citations` (c-2): 리서치 대응 핀에 부기가 있는데 서면 핀에 없으면
  **⚠️(부기 이관 누락)** — 판정 기준 명문화(C4를 "⚠️가 맞다"로 통일).
- `templates/render_서면.py` MARK_RE에 `[행위시 확인…]` 추가 — **빨간색**
  (출처 핀과 동일 취급, 제출 전 제거 대상).
- `[cite_check…]` 라인은 종전대로 리서치 전용(서면 금지) — 불변.

### 결정 ③ 부존재 사실 단정 3분법 (내용 기준 — C5·C6)

판정 기준을 "확인필요 태그 병기 여부"가 아니라 **근거 유무 + 어투**로 규정:

1. 입력 자료가 명시적으로 뒷받침(의뢰인 진술 문장 포함)하는 부존재 단정
   → **정상** (단정 어투 허용, 근거 표기 필수)
2. 입력 근거 없음 + **완화 어투**("…한 사실이 확인되지 않습니다") +
   `[변호사 확인 필요]` → **정상** (draft의 표준 작법)
3. 입력 근거 없음 + **단정 어투**("…한 사실이 전혀 없습니다")
   → **❌ 사실 생성** (태그 병기 여부 무관)

배치(문서 간 역할):
- `CLAUDE.md` 안전수칙 1에 한 문장 보강: "부존재·부작위의 단정도 사실 생성이다
  — 입력이 명시적으로 뒷받침하지 않으면 완화 어투 + 확인필요로 기재."(총칙)
- 3분법 전문은 `verify-citations` 프롬프트 4절(사실 주장 검사)에 판정 기준으로,
  `draft-complaint`·`draft-brief`에 작성 가드로 동일 문구 삽입.
  (파일 신설은 YAGNI로 비채택 — 문구가 짧아 3곳 동기화 부담 낮음)

### 결정 ④ draft 렌더 전 자체 점검 — 경량 3항 (준비서면 1차 FAIL 공통 대응)

`draft-complaint`·`draft-brief`에 "렌더 전 자체 점검" 절 신설 —
`check_projection.py` 실행 직전에:

1. 조문·판례 언급 문장 전수 → 핀 존재 + 리서치 원문 발췌 대응 확인
2. 사실 주장 전수 → `사건컨텍스트.사실관계`(근거 포함) 대응 확인
3. 부존재·부작위 단정 스캔 → 결정 ③ 기준 적용

- 결과는 **대화창 보고 1줄**("자체 점검: 핀 n/n, 사실근거 n/n, 부존재단정 0건").
  파일 산출 없음(검증 라인 오염 방지). 실패 항목은 렌더 전 수정.
- verify는 불변 — 자체 점검은 사전 필터일 뿐, verify는 여전히 전수 재검하며
  자체 점검 결과를 신뢰하지 않는다(독립성 유지).
- 중량 대안(사전 서브에이전트 검증)은 비용 2배·verify 중복으로 비채택.
