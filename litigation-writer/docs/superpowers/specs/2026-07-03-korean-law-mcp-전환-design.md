# 법령·판례 출처를 korean-law-mcp로 전환 — 설계문서

- 작성일: 2026-07-03
- 상태: 사용자 승인됨 (설계 검토 → 구현 계획 이행 예정)
- 대상 환경: Claude Code (Windows 11), 단독 사용자(변호사 1인). Codex 듀얼호스트 유지.

## 1. 목적과 범위

법령 기반 서면 작성의 **데이터 소스와 검증 방법론**을, 로컬 git 저장소
(`legalize-kr`·`precedent-kr`) 대조 방식에서 **korean-law-mcp**
(<https://github.com/chrisryugj/korean-law-mcp>) 대조 방식으로 전환한다.

전환으로 얻는 것:
- 법령·판례에 더해 **행정규칙·자치법규·조약·해석례** 등 도메인 확장
- 시행일 기준의 정확한 **행위시법(applicable_law)** 조회
- 12만 파일 `git grep` 역검색을 대체하는 **cite_check**(역인용 추적) 생사확인
- 두 대형 저장소 클론 유지 부담 제거

**보존해야 하는 것 (프로젝트 안전 원칙 — 변경 대상 아님):**
- 사실 생성 금지 / 근거 필수
- **인용 단일 진입로** — 서면 인용은 `리서치/쟁점별_법리.md`에 원문 발췌가
  있는 것만 가능
- **독립 검증 게이트** — 작성자를 신뢰하지 않는 독립 서브에이전트가 전수 대조
- 기계 검증 가능성(재현성)

| 항목 | 결정 |
|---|---|
| 데이터 소스 | git 저장소 2종 → korean-law-mcp (로컬 stdio) |
| 재현성 모델 | **스냅샷 동결 하이브리드** (§3) |
| MCP 접근 | 로컬 stdio 설치형, `.mcp.json` 커밋, `LAW_OC` 환경변수로 API 키 분리 |
| 도메인 범위 | 법령+판례 상시 스윕 + 4개 도메인 쟁점별 적응 (§5) |
| 구 저장소 | 클론 절차·저장소 검색규칙 전면 삭제 (사용자 "버리고" 지시) |

## 2. korean-law-mcp 역량 (근거)

- 9개 도구: `legal_research`, `legal_analysis`, `search_law`, `get_law_text`,
  `get_annexes`, `search_decisions`, `get_decision_text`, `discover_tools`,
  `execute_tool`
- `legal_analysis` 모드: `verify_citations`(환각 탐지), `cite_check`(역인용
  추적 기반 판례 유효성), `applicable_law`(시점별 버전 + 경과규정),
  `impact_map`
- 데이터원: 국가법령정보센터 Open API. **무료 API 키** 필요
  (`open.law.go.kr`), `LAW_OC` 환경변수 주입 가능
- 안정 식별자 반환: `lawId`, `MST`, 조번호, 판례일련번호. 상태 라벨
  `[현행]`/`⚠️[연혁-과거버전]`
- 설치: `npm install -g korean-law-mcp` / `npx korean-law-mcp setup`
  (Node 18+). 원격 엔드포인트도 존재하나 본 설계는 로컬 stdio 채택.

## 3. 재현성 모델 — 스냅샷 동결 하이브리드 (핵심)

git 해시는 불변이었으나 라이브 API는 시간이 지나면 결과가 달라질 수 있다
(법 개정). 재현성은 다음으로 보존한다:

1. **동결(freeze):** `/legal-research` 단계에서 MCP가 반환한 **원문 발췌를
   blockquote로 리서치 파일에 그대로 얼려둔다.** (기존과 동일 — 원문 발췌는
   이미 파일에 남았다.)
2. **재조회 앵커:** 발췌 옆 출처 핀에 **안정 ID**(법령: `MST`+조번호,
   판례: `판례일련번호`)와 **조회일**을 기록한다.
3. **독립 대조:** `/verify-citations` 서브에이전트는 그 ID로 MCP를 **재조회**해
   동결 발췌와 문자 대조한다. 리서치 파일의 판정 라인은 신뢰하지 않는다.

즉 git 저장소의 역할("검증자가 대조할 불변 재조회 경로")만
`git show/grep` → `MCP get_law_text/get_decision_text(ID)` 로 교체된다.
방법론의 뼈대(단일 진입로·기계검증·독립검증)는 불변.

## 4. 새 출처 핀 체계 (`rules/인용규칙.md` 개정)

**법령** (파일경로 → 안정 ID + 시행일 상태):

    현행:  [출처: 근로기준법 제27조 | MST:267581 | 시행 2021-11-19 [현행] | 조회 2026-07-03]
    행위시: [출처: 근로기준법 제27조 | MST:248613 | 시행 2019-01-15 [연혁] | 기준일 2020-05-01 | 조회 2026-07-03]

**판례** (파일명 → 판례일련번호):

    [출처: 대법원 2010. 3. 25. 선고 2009다12345 판결 | 판례일련번호:68012 | 조회 2026-07-03]
    [cite_check: 2026-07-03 조회 — 역인용 추적상 변경·폐기 미발견]

**신규 도메인**(행정규칙·자치법규·조약·해석례): 동일 패턴
`본문표기 | 도메인ID | 조회일`. 구체 ID 필드명은 구현 시 각 도구 응답으로 확정.

- 재현: 누구든 `get_law_text(MST)` / `get_decision_text(판례일련번호)` 로
  같은 원문을 재조회 → 동결 blockquote와 대조.
- 초안 DOCX까지 핀 유지 규칙(§3-3, 빨강/파랑 표시)은 불변.

## 5. 도메인 활용 규칙 (`legal-research` 스킬)

- **상시 기본 스윕:** 모든 쟁점에서 법령(`search_law`/`get_law_text`) +
  판례(`search_decisions`/`get_decision_text`).
- **쟁점별 적응 추가:** 쟁점 성격이 맞을 때만 추가 도메인 조회 —
  - 세무·조세 → 해석례(국세청)·조세심판례
  - 인허가·행정처분 → 행정규칙
  - 지방자치·조례 관련 → 자치법규
  - 국제거래·외국 요소 → 조약
- 스킬에 도메인 판단 기준을 명시. 무관한 도메인은 조회하지 않는다(토큰 절약).

## 7. 검증 게이트 재설계 (독립성 보존)

- 존재/내용일치: `get_law_text(MST)`·`get_decision_text(판례일련번호)`
  재조회 → 동결 발췌와 문자 대조 (조번호만 맞고 내용 다르면 ❌)
- 현행성: 재조회 결과 `[현행]/[연혁]` 라벨 vs 핀
- 행위시: `applicable_law(법령, 기준일)` 재실행 → 핀의 MST·시행일 대조
- 생사확인: `cite_check(판례)` 재실행 — 리서치 라인 불신
- **MCP `verify_citations` 위임 안 함** (블랙박스 회피). 우리 검증자는
  개별 도구로 원문을 직접 재조회해 대조한다.
- 판정 표(✅/⚠️/❌), PASS/FAIL 종합, 재작성 루프, 시니어 조언(대화창 전용)은 불변.

## 8. 골든 케이스 회귀 점검 재정의

라이브 API라 바이트 동일 멱등은 불가하므로:
- 골든 케이스(`cases/2026_김민재 해고 무효`)를 MCP 기준으로 **1회 재베이스라인**
- 회귀 점검 기준: ① 산출 형식 정상 ② 검증 PASS/FAIL 불변 ③ 사건컨텍스트 멱등
- **현행성 ⚠️ 라인은 법 개정 시 정당하게 바뀔 수 있어 diff 대상에서 제외**
  (회귀가 아니라 정상 동작)

## 9. 롤아웃 순서

1. `.mcp.json` + `LAW_OC` 설정, MCP 연결·도구 스모크 테스트

## 10. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| API 키 미보유·발급 지연 | 롤아웃 1단계에서 키 발급·스모크 테스트를 게이트로. 키 없으면 이후 단계 진행 불가 명시 |

| 라이브 드리프트로 검증 재현 실패 | 스냅샷 동결(§3) + 조회일 기록. ⚠️는 정상 신호로 취급 |
| Codex에서 MCP 미동작 | Codex MCP 설정 문서화. 실패 시 Claude Code 우선, Codex 베스트에포트 |
| 신규 도메인 ID 필드 불명확 | §4 신규 도메인 핀은 구현 시 실제 응답으로 확정(설계는 패턴만 고정) |

## 11. 범위 밖 (YAGNI)

- MCP 원격 커넥터 방식 (로컬 stdio 채택)
- 자동화 회귀 스크립트 (기존 방침대로 수기 서브에이전트 재실행 유지)
- 사건컨텍스트 스키마 대규모 개편 (도메인 힌트 필드는 선택·최소)
