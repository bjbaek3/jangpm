# 송무서면 생성기 웹 앱 배포 — 설계문서

- 작성일: 2026-07-21
- 상태: 사용자 승인 대기 (브레인스토밍 완료, 시스템 설계·화면 기획 구두 승인됨)
- 스택: Next.js(App Router) + Tailwind + shadcn/ui + Supabase + Vercel + **Anthropic Managed Agents**(베타)

## 1. 목표와 배경

현재 로컬 Claude Code 워크스페이스(스킬 5종 + rules + templates + korean-law-mcp)를
소규모 팀/사무실이 브라우저로 쓰는 웹 앱으로 배포한다. 핵심 가치는 기존과 동일 —
**검수 게이트가 있는 송무서면 파이프라인**(사건구성 → 리서치 → 서면작성 → 인용검증)을
변호사가 단계별로 통제하며 진행하는 것.

### 검증된 전제 (2026-07-21, claude-code-guide 조사)

- Agent SDK/Managed Agents는 스킬(.claude/skills), 시스템 프롬프트, MCP, 세션 재개를 지원.
- **Managed Agents는 stdio MCP 미지원(HTTP URL 방식만)** → korean-law-mcp를 HTTP MCP
  래퍼로 재노출하는 것으로 해소 (§6).
- 관리형 샌드박스: Python+pip 가능(docxtpl 렌더 OK, 단 세션마다 재설치),
  Files API로 파일 반출입(세션당 100파일), 세션 idle 중 컴퓨트 무과금,
  실행 중 $0.08/시간 + 표준 토큰비. 베타 헤더 `managed-agents-2026-04-01`.
- 근거: platform.claude.com/docs/en/managed-agents/{overview,mcp-connector,files,sessions,events-and-streaming,self-hosted-sandboxes}

## 3. 아키텍처

```
브라우저 (Next.js UI, shadcn)
   │
   ├─ Vercel: Next.js App Router
   │    ├─ 페이지·API 라우트 (사건 CRUD, 실행 트리거, 검수 액션)
   │    ├─ /api/runs/[id]/stream  ← Managed Agents SSE 프록시 (API 키 은닉)
   │    └─ /api/mcp/korean-law    ← HTTP MCP 래퍼 (korean-law-mcp 도구 재노출, LAW_OC 서버 env)
   │
   ├─ Anthropic Managed Agents (베타)
   │    └─ 에이전트 정의 1개: 스킬 5종 + rules/ + templates/ 번들
   │       시스템 프롬프트 = CLAUDE.md 안전수칙 + 웹 어댑테이션 오버레이
   │       MCP = 위 HTTP 엔드포인트
   │
   └─ Supabase
        ├─ Auth: 이메일 로그인(초대 기반), 역할 관리자/멤버
        ├─ Postgres: 사건·실행·체크포인트·검수·사용량 (RLS 팀 단위)
        └─ Storage: 입력 파일·산출물 전 버전 (비공개 버킷 + 서명 URL)
```

**핵심 원칙 — Supabase가 진실의 원천.** 관리형 샌드박스 파일시스템은 세션 간 지속이
보장되지 않으므로, 로컬 `cases/` 폴더의 역할을 Supabase가 맡는다. 단계 실행 시작 시
필요 파일을 세션에 주입(hydrate)하고, 종료 시 산출물을 Files API로 회수(harvest)해
버전 저장한다. 세션이 언제 소멸해도 데이터 유실이 없고, 단계마다 새 세션이어도 무방.

**리포 구조 — 모노리포.** 웹 앱은 이 리포의 `apps/web/`에 둔다. 이유: `.claude/skills/`와
`rules/`·`templates/`가 canonical인 리포에서 에이전트 번들을 직접 빌드해 동기화 기계를
없앤다. Vercel 배포 시 `cases/`(의뢰인 데이터)와 무관 디렉토리는 `.vercelignore`로 제외.
(대안: 별도 리포 + 서브모듈 — 동기화 부담 때문에 비채택.)

## 4. 데이터 모델 (Postgres)

- **profiles** — 팀 멤버(auth.users 연동), 역할 `admin | member`
- **cases** — 사건: 제목, 상태, 담당자, 생성자. 사건은 팀 전체 공개(사건별 접근 제한은 v2)
- **rounds** — 라운드: 사건 FK, 유형 `소장 | 준비서면`, 순번. 파이프라인 반복 단위
- **runs** — 단계 실행: 라운드 FK, 단계 `intake | research | draft | verify`,
  상태 `running | waiting_checkpoint | succeeded | failed | canceled`,
  Managed Agents 세션 ID, 토큰 사용량, 비용
- **checkpoints** — run FK, 유형 `쟁점승인 | 질문`, payload JSON, 응답 JSON, 상태
- **case_files** — 파일 메타: 사건 FK, 종류 `입력 | 사건컨텍스트 | 리서치 | 서면 | 검증보고 | context_json`,
  Storage 경로, 버전 번호, 생성 run FK (어느 실행이 만든 버전인지 추적)
- **reviews** — 검수 게이트 기록: 라운드 FK, 단계, 결정 `승인 | 수정지시`, 지시문, 검수자

RLS: 전 테이블 팀 스코프. Storage: 비공개 버킷, 다운로드는 서명 URL.

## 5. 실행 모델 (단계 1회 실행의 생애주기)

1. 사용자 [단계 실행] → API가 `run` 생성 → Managed Agents 세션 시작.
   프롬프트 = 해당 스킬 실행 지시 + Files API로 워크스페이스 파일 마운트
2. `/api/runs/[id]/stream`이 Managed Agents SSE를 브라우저로 프록시 → 실행 콘솔 타임라인
3. 에이전트가 질문·쟁점 승인 필요 시 **체크포인트 프로토콜**(§5.1) 출력 → 세션 idle
   (무과금) → UI 체크포인트 카드 → 사용자 응답 → `user.message` 이벤트로 재개.
   며칠 뒤 응답해도 이어짐
4. 단계 완료 → 산출물 harvest → Supabase 버전 저장 → run `succeeded` → **검수 게이트 상태**
5. 변호사 검수 → [승인](다음 단계 잠금 해제) 또는 [수정 지시](지시문 포함 동일 단계 재실행)
6. verify에 ❌ 하나라도 → 사건에 **"제출 금지"** 배지 + 이후 진행 잠금 (기존 게이트 규칙 동일)
7. **시니어 변호사 조언**: verify 직후 스트림으로 일회성 표시만, **DB 저장 금지**
   (기존 "대화창에만 출력" 규칙의 웹 번역)

### 5.1 체크포인트 프로토콜

에이전트는 사용자 입력이 필요하면 마지막 메시지에 펜스 블록으로 출력하고 idle 한다:

````
```checkpoint
{ "type": "쟁점승인" | "질문", "payload": { ... } }
```
````

웹 백엔드가 이 블록을 파싱해 checkpoints 레코드 생성 → UI 카드 렌더 → 응답을
`user.message`로 회신. **스킬 파일은 수정하지 않는다** — 시스템 프롬프트 오버레이가
"AskUserQuestion 대신 checkpoint 블록 출력"으로 매핑한다 (§7).

## 6. HTTP MCP 래퍼 (`/api/mcp/korean-law`)

- korean-law-mcp(npm, stdio)는 국가법령정보센터 공개 REST API를 호출하는 무상태
  도구 모음 → streamable HTTP MCP로 재노출하기 적합
- 구현: Next.js 라우트에서 MCP streamable HTTP 서버로 도구 재노출.
  1순위: korean-law-mcp를 라이브러리로 import해 도구 정의 재사용.
  불가하면 2순위: 요청마다 stdio 자식 프로세스 브리지. 그것도 부적합하면
  3순위: 도구 시그니처를 유지한 채 Open API 직접 호출로 재구현
- 인증: 래퍼 엔드포인트에 공유 시크릿 헤더(Managed Agents 설정에 포함),
  `LAW_OC`는 Vercel 서버 env
- 성공 기준: 기존 스킬들이 쓰는 도구 이름·입출력이 로컬 stdio 때와 동일하게 동작
  (스킬 무수정 원칙)

## 7. 에이전트 패키징

- 에이전트 정의 1개에 스킬 5종 + `rules/` + `templates/` 번들
- 시스템 프롬프트 = 루트 CLAUDE.md의 안전수칙·워크플로우 + **웹 어댑테이션 오버레이**:
  - 파일 경로: `cases/{폴더}/...` → 세션 워크스페이스 마운트 경로 매핑
  - AskUserQuestion → 체크포인트 프로토콜 (§5.1)
  - "대화창에만 출력"(시니어 조언) → 스트림 전용 마커로 출력, 파일 기록 금지 유지
- 세션 셋업: pip install docxtpl 등 의존성 설치 스텝 포함 (세션당 반복, 수십 초)
- 번들 빌드 스크립트가 리포의 canonical 원본에서 생성 — 수동 복사 금지

## 8. 화면 기획

### IA

```
로그인
└─ 사건 목록 (홈)
   ├─ 새 사건 등록
   ├─ 사건 상세  ←― 핵심 화면
   │    ├─ 파이프라인 스테퍼 (라운드 단위 4단계)
   │    ├─ 탭: 개요 | 입력자료 | 사건컨텍스트 | 리서치 | 서면 | 검증보고
   │    ├─ 실행 콘솔 (우측 드로어): 타임라인 + 체크포인트 카드
   │    └─ 시니어 조언 모달 (일회성)
   └─ 설정: 멤버 | 연동 상태 | 사용량
```

파이프라인은 **라운드** 단위 반복: 라운드 1(소장) = 사건구성→리서치→소장→인용검증.
답변서 도착 시 라운드 2(준비서면) = 답변서 업로드→리서치 보강→준비서면→인용검증.
라운드는 계속 추가 가능.

### 화면별 요지

1. **로그인** — Supabase Auth 이메일. 가입은 관리자 초대 링크만
2. **사건 목록** — 테이블: 사건명/담당/미니 스테퍼/상태 배지/최근 활동.
   배지: `대기` `실행중` `응답 필요` `검수 대기` `제출 금지`(빨강) `완료`.
   변호사 할 일(응답 필요·검수 대기)이 가장 눈에 띄어야 함
3. **새 사건 등록** — 사건명, 담당자, 텍스트 붙여넣기 + 파일 드래그(복수).
   등록 후 사건 상세로 이동
4. **사건 상세** — 헤더(사건명·배지·담당) / 스테퍼(단계 상태 + 실행·재실행, 미승인
   다음 단계 잠금, 라운드 드롭다운) / 탭 본문 + 우측 실행 콘솔 드로어
5. **산출물 뷰어(탭)** — 검수 대기 탭 상단에 게이트 바 `[승인하고 다음 단계로]`
   `[수정 지시…]`:
   - 사건컨텍스트: 당사자 카드, 사실관계 표(일자/내용/근거), 쟁점 카드, 청구 요약,
     확인필요 체크리스트(빨간 강조)
   - 리서치: 쟁점별_법리.md 렌더 + 쟁점 앵커 목차
   - 서면: 텍스트 미리보기 + [DOCX 다운로드] + 버전 히스토리
   - 검증보고: 인용별 PASS/FAIL 표, ❌ 시 상단 빨간 "제출 금지" 경고
6. **실행 콘솔** — 접이식 타임라인(요약 → 펼치면 상세), 인라인 체크포인트 카드
   (쟁점 승인: 표 + 행 수정·삭제·추가 + 일괄 승인 / 질문: 폼), idle 무과금 안내,
   [실행 취소]
7. **시니어 조언 모달** — verify 통과 직후 1회 표시, "⚠ 이 조언은 어디에도 저장되지
   않습니다" 라벨, 닫으면 소멸(재실행 시에만 재생성)
8. **설정** — 멤버(초대·역할, 관리자만) / 연동 상태(Anthropic·LAW_OC·MCP 래퍼
   헬스체크 + Managed Agents 세션 데이터 서버 보관 고지) / 사용량(사건별·월별
   토큰·비용, 단계당 비용 상한 설정)

### Pencil 핸드오프

화면별 위임 프롬프트는 `docs/superpowers/specs/2026-07-21-웹앱-pencil-프롬프트.md`.
공통 디자인 언어 블록(shadcn 기반, 한국어 UI, 차분한 법률 도구 톤) + 화면 11종
(사건 상세는 상태 변형 5종 포함). 디자인 실행은 사용자가 Pencil MCP로 직접.

## 9. 오류·비용·보안

- **실행 실패**: run `failed` 기록, 산출물 미반영(이전 버전 유지), 재실행 버튼,
  세션 로그 조회 가능
- **비용 통제**: run별 토큰·비용 기록 → 설정에 집계. **단계당 비용 상한 기본 $5**
  (설정에서 변경) 초과 시 자동 중단
- **보안**: RLS 팀 격리, 비공개 Storage + 서명 URL, API 키·LAW_OC 서버 env 전용.
  Managed Agents 세션에 사건 자료가 Anthropic 서버에 보관됨을 설정 화면에 고지
- **베타 리스크 헤지**: 에이전트 실행부를 어댑터 인터페이스(실행 시작/스트림/체크포인트
  응답/파일 반출입)로 분리 — Managed Agents가 막히면 상주 워커(Agent SDK 컨테이너)
  구현체로 교체 가능하게. 사용자 지시: **목표에 어긋나는 상황이 오면 방향 전환을
  먼저 제안할 것**

## 10. v1 제외 (명시적)

- 산출물 직접 편집기 (수정은 "수정 지시" 재실행으로만)

- 사건별 접근 제한 (팀 전체 공개)
- DOCX 웹 렌더링 미리보기 (텍스트 미리보기 + 다운로드만)
- 과금·외부 SaaS 기능 (팀 내부 도구)
- 로컬 Claude Code 워크플로우 폐지 — 웹과 병행 유지 (골든 케이스 회귀 점검도 로컬 유지)

## 11. 테스트 전략

- MCP 래퍼: 도구별 golden 요청/응답 스냅샷 (로컬 stdio 결과와 대조)
- 체크포인트 프로토콜: 파서 단위 테스트 + 왕복(질문→응답→재개) 통합 테스트
- 파이프라인 E2E: 골든 케이스(2026_김민재 해고 무효) 입력으로 스테이징에서 1회 완주,
  검증보고 PASS/FAIL이 로컬 실행과 동일한지 확인
- UI: 핵심 흐름(사건 등록→intake 실행→쟁점 승인→검수 승인) Playwright 스모크
