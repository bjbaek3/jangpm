## Problem

리서치 단계 에이전트 실행이 연쇄 실패("완료/체크포인트 마커 없이 세션이 종료됨").
사건구성 단계는 성공. 세션 이벤트를 보면 `agent.mcp_tool_use` 발행 직후 tool_result
없이 ~200ms 만에 세션이 idle로 전환 — 에러 이벤트가 전혀 없어 원인이 안 보였다.

## Solution

에이전트 생성 시 `mcp_toolset`에 `default_config.permission_policy`를 명시하지 않으면
기본값이 `always_ask`다(`agent_toolset_20260401` 기본값은 `always_allow`로 서로 다름).
승인 대기 상태가 곧 idle이라 클라이언트에는 에러가 아닌 정상 idle로 보인다.
`{ type: "mcp_toolset", mcp_server_name: "...", default_config: { enabled: true,
permission_policy: { type: "always_allow" } } }`로 명시해 해결(a649ad0).
추가로 도구 구성을 `computeConfigHash` 입력에 포함해야 코드 수정만으로
재프로비저닝이 트리거된다 — 기존 해시는 도구 구성을 안 봐서 고쳐도 옛 에이전트를
계속 재사용했을 것이다.

## Key Insight

MCP를 쓰는 단계만 죽고 안 쓰는 단계는 성공하는 패턴 + `mcp_tool_use` 직후
결과 없이 idle이면 권한 정책을 의심하라. 그리고 프로비저닝 캐시 키(config hash)에는
서버에 보내는 구성 전체가 들어가야 한다 — 빠진 필드는 고쳐도 배포에 반영되지 않는다.
